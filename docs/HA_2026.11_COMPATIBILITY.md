# Home Assistant 2026.11 compatibility audit

Scope: the integration code and manifest were checked against the Home Assistant Core 2026.9–2026.11 changes relevant to custom integrations. This is a source-level audit; CI validation remains the authority for hassfest, HACS, and the test suite.

## Checked, not affected

- **Device registry config-entry properties:** no reads of `DeviceEntry.config_entries`, `config_entries_subentries`, or `primary_config_entry` were found. Device registration uses `config_entry_id`.
- **Config-flow reload deprecation:** the options flow saves through `async_create_entry`; the config flow does not use `async_update_reload_and_abort` or another config-flow reload method alongside its update listener.
- **Entity lifecycle changes in 2026.11:** the platform entities do not override `async_added_to_hass`, `async_will_remove_from_hass`, or `async_prepare_to_add_to_hass`, so they do not need to opt in to in-place entity-ID changes.
- **Service callbacks:** registered service handlers accept `ServiceCall`; no removed legacy service callback signature was found.
- **Manifest and translations:** the existing manifest keys, config-flow definitions, and translation files contain no identified 2026.9–2026.11 deprecation requiring a compatibility change.

## Changed

- Documentation only: record the compatibility review so the checks and rationale are available alongside the integration.
- No runtime change and no minimum Home Assistant version increase are justified by the APIs reviewed. Home Assistant's contributor guidance explicitly keeps boolean return values supported for custom integrations, so those alone are not a migration requirement.
